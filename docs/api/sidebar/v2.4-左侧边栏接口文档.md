# 左侧边栏 - 文档管理与菜单配置接口文档 (v2.4)

## 概述
本文档专注于定义 MarkFlow 系统中**左侧边栏（LeftSidebar）**相关的 RESTful API，采用扁平化设计，与中间编辑区和右侧属性面板的数据拉取逻辑完全解耦。主要涵盖侧边栏目录树的获取、菜单状态的持久化、以及基础文档节点的管理。

## 基础信息
- **Base URL**: `https://api.markflow.com/v2.4/sidebar`
- **数据交互格式**: `application/json`
- **鉴权方式**: HTTP Header `Authorization: Bearer <Token>`

---

## 1. 获取侧边栏配置状态
拉取用户最后一次保存的左侧边栏布局配置（如主导航高亮项、树形目录的展开折叠状态等），用于页面初始化渲染。

- **接口路径**: `/preferences`
- **请求方法**: `GET`

### 请求参数
无

### 响应字段说明
| 字段名 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `code` | `integer` | 是 | 业务状态码 (200表示成功) |
| `message` | `string` | 是 | 响应描述信息 |
| `data` | `object` | 是 | 配置数据对象 |
| `data.activeNavItem` | `string` | 是 | 当前激活的主导航标识（如: `files`, `graph`, `search`） |
| `data.expandedNodes` | `array` | 是 | 当前处于展开状态的目录树节点 ID 数组（如: `['doc-space', 'architecture']`） |
| `data.isLeftSidebarOpen`| `boolean`| 是 | 左侧边栏是否处于展开状态 |
| `data.filesCount` | `integer` | 否 | 文档库中的文件总数（用于显示菜单徽标，如: 24） |
| `data.tagsCount` | `integer` | 否 | 知识标签的总数（用于显示菜单徽标，如: 12） |

### 响应示例
```json
{
  "code": 200,
  "message": "success",
  "data": {
    "activeNavItem": "files",
    "expandedNodes": ["doc-space", "architecture", "api-specs", "bookmarks"],
    "isLeftSidebarOpen": true,
    "filesCount": 24,
    "tagsCount": 12
  }
}
```

## 2. 更新侧边栏配置状态
当用户在左侧边栏进行点击切换、折叠展开等交互时，增量同步配置状态至服务端进行持久化。

- **接口路径**: `/preferences`
- **请求方法**: `PATCH`

### 请求字段说明 (Body)
> 注：采用扁平化设计，支持增量更新，传递需要修改的字段即可。

| 字段名 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `activeNavItem` | `string` | 否 | 需要更新的主导航标识 |
| `expandedNodes` | `array` | 否 | 需要更新的展开节点 ID 数组 |
| `isLeftSidebarOpen`| `boolean`| 否 | 左侧边栏的开闭状态 |

### 请求参数示例
```json
{
  "activeNavItem": "graph",
  "expandedNodes": [
    "doc-space",
    "architecture"
  ],
  "isLeftSidebarOpen": true
}
```

### 响应字段说明
| 字段名 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `code` | `integer` | 是 | 业务状态码 |
| `message` | `string` | 是 | 操作结果提示 |

### 响应示例
```json
{
  "code": 200,
  "message": "侧边栏配置更新成功"
}
```

## 3. 获取左侧目录树结构
用于渲染左侧边栏中“目录树结构”区域的层级数据，该接口与具体文档详情的内容拉取解耦，仅返回渲染树所需的扁平化元数据。

- **接口路径**: `/tree-nodes`
- **请求方法**: `GET`

### 请求参数 (Query)
| 参数名 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `parentId` | `string` | 否 | 指定父节点 ID 进行懒加载拉取；不传则返回顶层基础骨架 |

### 请求参数示例
```json
{
  "parentId": "architecture"
}
```

### 响应字段说明
| 字段名 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `code` | `integer` | 是 | 业务状态码 |
| `data` | `array` | 是 | 节点列表数组 (扁平化结构，通过 parentId 关联) |
| `data[].id` | `string` | 是 | 节点唯一标识符 |
| `data[].parentId` | `string`| 否 | 父节点 ID，顶层节点为空 |
| `data[].type` | `string` | 是 | 节点类型: `folder`(文件夹) / `document`(文档) |
| `data[].title` | `string` | 是 | 节点显示名称 (如: `ADR-004-存储选型.md`) |
| `data[].status` | `string` | 否 | 文档状态，仅 document 类型存在 (如: `review`, `final`, `draft`) |
| `data[].hasChildren`| `boolean`| 是 | 是否包含子节点，用于决定是否渲染展开箭头 |

### 响应示例
```json
{
  "code": 200,
  "data": [
    {
      "id": "architecture",
      "parentId": null,
      "type": "folder",
      "title": "架构设计 (Architecture)",
      "hasChildren": true
    },
    {
      "id": "doc_101",
      "parentId": "architecture",
      "type": "document",
      "title": "ADR-004-存储选型.md",
      "status": "review",
      "hasChildren": false
    }
  ]
}
```

## 4. 获取常驻书签列表
用于渲染左侧边栏底部“常驻书签 (BOOKMARKS)”区域的快捷入口列表。

- **接口路径**: `/bookmarks`
- **请求方法**: `GET`

### 请求参数
无

### 响应字段说明
| 字段名 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `code` | `integer` | 是 | 业务状态码 |
| `data` | `array` | 是 | 书签节点数组 |
| `data[].id` | `string` | 是 | 书签/文档对应的唯一标识符 |
| `data[].title` | `string` | 是 | 书签显示名称 |
| `data[].url` | `string` | 否 | 跳转路由或外部链接（如果是外部链接则通常以 http 开头） |
| `data[].iconColor`| `string` | 否 | 书签图标的自定义颜色（如：`#f59e0b`） |

### 响应示例
```json
{
  "code": 200,
  "data": [
    {
      "id": "doc_bookmark_01",
      "title": "快速指引: 研发规范.md",
      "url": "/docs/doc_bookmark_01",
      "iconColor": "#f59e0b"
    },
    {
      "id": "doc_bookmark_02",
      "title": "API 接入指南",
      "url": "/docs/doc_bookmark_02",
      "iconColor": "#3b82f6"
    }
  ]
}
```

## 5. 新建目录 (文件夹)
对应左侧边栏“目录树结构”区域右上角的 `+` (新建目录) 按钮。用于在指定层级下创建一个新的空文件夹节点。

- **接口路径**: `/tree-nodes/folder`
- **请求方法**: `POST`

### 请求字段说明 (Body)
| 字段名 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `title` | `string` | 是 | 目录名称（如: `后端微服务`） |
| `parentId` | `string` | 否 | 父节点 ID，不传或传 `null` 则表示在根目录创建 |

### 请求参数示例
```json
{
  "title": "后端微服务",
  "parentId": null
}
```

### 响应字段说明
| 字段名 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `code` | `integer` | 是 | 业务状态码 |
| `message` | `string` | 是 | 操作结果提示 |
| `data` | `object` | 是 | 新创建的目录节点数据 |
| `data.id` | `string` | 是 | 新目录的唯一标识符 |
| `data.parentId` | `string` | 否 | 父节点 ID |
| `data.type` | `string` | 是 | 节点类型，固定为 `folder` |
| `data.title` | `string` | 是 | 节点显示名称 |
| `data.hasChildren`| `boolean`| 是 | 是否包含子节点，初始固定为 `false` |

### 响应示例
```json
{
  "code": 200,
  "message": "创建成功",
  "data": {
    "id": "folder_new_101",
    "parentId": null,
    "type": "folder",
    "title": "后端微服务",
    "hasChildren": false
  }
}
```

## 6. 编辑/重命名目录 (文件夹)
修改已存在的文件夹节点信息（主要用于重命名）。

- **接口路径**: `/tree-nodes/folder/{id}`
- **请求方法**: `PUT`

### 请求参数 (Path)
| 参数名 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `id` | `string` | 是 | 需要修改的目录 ID |

### 请求参数 (Body)
| 参数名 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `title` | `string` | 是 | 修改后的新文件夹名称 |

### 响应示例
```json
{
  "code": 200,
  "message": "修改成功",
  "data": {
    "id": "folder-123",
    "title": "已重命名的目录",
    "type": "folder",
    "parentId": "root"
  }
}
```

## 7. 删除目录 (文件夹)
删除指定的目录及其下的所有子节点内容。这是一个高危操作，前端通常需要二次弹窗确认。

- **接口路径**: `/tree-nodes/folder/{id}`
- **请求方法**: `DELETE`

### 请求参数 (Path)
| 参数名 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `id` | `string` | 是 | 需要删除的目录节点 ID |

### 响应字段说明
| 字段名 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `code` | `integer` | 是 | 业务状态码 |
| `message` | `string` | 是 | 操作结果提示 |
| `data` | `null` | 否 | 删除操作不返回数据实体 |

### 响应示例
```json
{
  "code": 200,
  "message": "删除成功",
  "data": null
}
```
